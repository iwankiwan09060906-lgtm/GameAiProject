# Qwen 상황 대사 기능정의서 · DB 설계 (Null Trace)

Nov 10, 2026 · @기완

## 개요·범위

적 NPC가 **소리·단서·시야** 이벤트를 인지하면, 게임이 그 순간의 상태값을 묶어 Qwen에 넘기고 Qwen은 **20자 이내 대사 한 줄**을 돌려준다. 이벤트는 기본 17종에 추가 5종을 더해 22종이다.

상태값은 **Qwen의 입력으로 넘긴다**. 상태 전환·의심도·이동·공격은 AI 설계(FSM·Utility·행동 트리)가 정하고, Qwen 출력은 말풍선과 연출에만 쓴다(설명서 14쪽, MASTER 7.18·7.22).

| 용어 | 뜻 |
| --- | --- |
| 이벤트(Event) | 월드에서 일어난 사건 1건. 코드·위치·시각·세기를 가짐. 예: 문이 열림 |
| 인지(Perception) | 특정 NPC가 그 이벤트를 듣거나 보거나 무전으로 받은 기록. 같은 이벤트도 NPC마다 따로 생김 |
| 상황 상태값(Context) | 인지 1건 + 그 NPC의 현재 상태·의심도 단계·성격·주변 상황을 묶은 값. Qwen의 입력 |
| 대사(Line) | Qwen이 돌려준 20자 이내 한 줄 + 감정 태그. 실패하면 기본 대사 |

1\~7장은 기능 정의, 8장은 MASTER\_PROMPT 반영 위치, 9장은 테이블·필드 정의(DB 설계)다.

## 이벤트 정의

이벤트는 모두 `분류_이름` 코드를 갖는다(`SND` 소리, `CLU` 단서, `SIG` 시야). 기본 17종에 더한 5종은 이름 뒤에 \*(추가)\*로 표시했다. 점수·반경·수명은 플레이 검증 전 초기값이며 모두 `event_type` 테이블에서 바꾼다.

의심도 기여 = **기본 점수 × 세기(0\~1) × 신뢰도(0\~1)** (설명서 7쪽 식). 세기는 소리면 거리·벽 감쇠(MASTER 7.6), 시각이면 거리·밝기(7.17)로 정한다. 대사 열의 **즉시**는 Qwen 없이 기본 대사를 바로 내는 긴급 이벤트, **Qwen**은 2초까지 기다리는 이벤트다. MASTER 열은 그 규칙이 들어 있는 MASTER\_PROMPT 절이다(22종 전체 표는 7.21).

## 처리 흐름과 기능 요구사항

한 이벤트는 **발생 → 인지 → 상황 묶기 → 요청 → 검증 → 표시** 6단계를 거친다. AI 판단은 2단계(인지)에서 끝나고, 3단계부터는 대사만 다룬다.

1. **발생** — 플레이어·무기·문·소품·조명이 `WorldEventBus`에 이벤트를 올린다. `world_event` 행이 하나 생긴다.
2. **인지** — 각 NPC의 센서(청각·시각·무전)가 조건을 검사해 `npc_perception` 행을 만들고 의심도에 기여를 더한다. 상태 전환은 기존 FSM·Utility가 한다.
3. **상황 묶기** — `BarkPicker`가 인지 1건과 NPC 상태를 합쳐 상황 상태값(Context)을 만든다.
4. **요청** — 즉시 이벤트는 기본 대사로 바로 6단계. 나머지는 캐시를 먼저 보고, 없으면 `bark_request`를 만들어 Qwen에 보낸다.
5. **검증** — 20자·금지어·반복·유효성(추적 번호·행동 번호·생존)을 검사한다. 실패하면 기본 대사.
6. **표시** — `BarkEvent`로 말풍선을 띄우고 `bark_line_history`에 남긴다. 감정 태그는 말풍선 연출에만 쓴다.

### 기능 요구사항

우선순위는 MASTER 2.3 기준(M 필수, S 권장, C 여유)이다.

| ID | 기능 | 내용 | 우선순위 |
| --- | --- | --- | --- |
| FR-01 | 이벤트 등록 | 22종 이벤트를 `event_type` 데이터로 정의하고, 코드 수정 없이 수치를 바꾼다 | M |
| FR-02 | 이벤트 발생 | 발생 주체가 `world_event`를 만들고 고유 ID·게임 시각·위치·세기를 기록한다 | M |
| FR-03 | 청각 인지 | `SND_*`는 MASTER 7.6 감쇠식으로 세기를 구하고 0.2 이상이면 인지한다. 바람 구역은 ×0.6 | M |
| FR-04 | 사물 인지 | `CLU_*`는 시야·차폐·거리·밝기 조건을 모두 만족하면 인지하고, 같은 물체는 NPC당 1회만 인지한다 | M |
| FR-05 | 문 기대 상태 | 맵 JSON의 문마다 평소 상태(열림/닫힘)를 두고, 다르면 `CLU_DOOR_OPEN`/`CLU_DOOR_CLOSED`를 만든다 | M |
| FR-06 | 중복 제거 | 같은 사건을 직접 듣고 무전으로도 받으면 점수를 두 번 더하지 않는다(설명서 13쪽) | M |
| FR-07 | 상황 묶기 | 4장 입력 규격대로 상태값을 만든다. NPC가 모르는 값(플레이어 좌표 등)은 넣지 않는다 | M |
| FR-08 | Qwen 요청 | 비동기 요청, 실제 시간 2초 한도, NPC당 1건 | M |
| FR-09 | 응답 검증 | 5장 규칙을 모두 통과한 대사만 표시한다 | M |
| FR-10 | 기본 대사 대체 | 실패·지연·꺼짐이면 이벤트·상태별 기본 대사를 연출 난수로 고른다 | M |
| FR-11 | 우선순위 큐 | 동시에 여러 요청이 있으면 6장 우선순위로 자리를 준다 | M |
| FR-12 | 반복 방지 | NPC별 최근 대사 5개와 전체 최근 10개를 프롬프트에 넣고 같은 대사는 버린다 | S |
| FR-13 | 감정 태그 | Qwen이 감정 5종 중 하나를 함께 돌려주고, 말풍선 색·흔들림에 쓴다 | S |
| FR-14 | 성격 | NPC마다 성격(`persona`)을 배정해 말투를 바꾼다 | S |
| FR-15 | 대사 캐시 | 같은 상황 키의 통과 대사를 저장해 재사용하고 호출 수를 줄인다 | S |
| FR-16 | 로그 | 요청·응답·결과를 `qwen_log`에 남기고 F3에서 통계를 보여 준다 | S |
| FR-17 | 동료 무응답 점검 | 소총병이 45초마다 무전 점검, 죽은 동료가 있으면 `CLU_NO_ANSWER` | S |
| FR-18 | 사전 생성 도구 | 에디터 메뉴에서 상황 키별 대사를 묶어 생성해 `bark_fallback`에 추가 후보로 저장 | S |
| FR-19 | 동료 대구 | 가까운 동료가 앞 대사에 짧게 답한다(7장) | C |

## Qwen 입력·출력 규격

Qwen에는 숫자 대신 **말로 된 구간값**만 넘긴다. 작은 모델은 숫자를 대사에 그대로 옮기기 쉽고("의심도 47이야"), 구간값이 캐시 키로 쓰기도 좋다.

### 입력 상태값

| 묶음 | 필드 | 값 | 만드는 규칙 |
| --- | --- | --- | --- |
| 사건 | `사건` | 이벤트 한국어 이름 | `event_type.name_ko` |
| 사건 | `분류` | 소리 / 단서 / 시야 | `event_type.category` |
| 사건 | `알게 된 경로` | 직접 / 무전 | 인지 출처 |
| 사건 | `방향` | 앞 / 뒤 / 왼쪽 / 오른쪽 | NPC 정면 기준 90° 4분할, 무전이면 생략 |
| 사건 | `거리` | 가까움 / 중간 / 멀음 | 4m 미만 / 4\~10m / 10m 초과 |
| 사건 | `시점` | 방금 / 조금 전 / 오래 전 | 2초 미만 / 10초 미만 / 그 이상 |
| 사건 | `반복` | 처음 / 두 번째 / 여러 번 | 같은 추적 동안 같은 코드 인지 횟수 |
| 사건 | `세부` | 예: 동료 이름, 평소 문 상태 | 이벤트별 허용 필드만(`event_type.detail_fields`) |
| NPC | `역할` | 경비병 / 소총병 | `enemies.json` 종류 |
| NPC | `성격` | 예: 결단한 고참 | `persona.label` |
| NPC | `업무` | 초소 대기 / 순찰 / 확인 / 수색 / 교전 준비 / 복귀 | 현재 목표(Utility) |
| NPC | `긴장도` | 평상 / 주의 / 수색 / 적극 수색 / 교전 준비 / 높은 위협 | 의심도 구간(설명서 7쪽) |
| NPC | `몸 상태` | 멀쩡 / 부상 / 위독 | 체력 70% 이상 / 30% 이상 / 미만 |
| NPC | `주변 동료` | 없음 / 한 명 / 여럿 | 10m 안 살아 있는 동료 수 |
| 환경 | `장소` | 실내 / 야외 | NPC 칸 바닥 |
| 환경 | `밝기` | 밝음 / 어두움 | NPC 칸 밝기 0.5 기준 |
| 환경 | `바람` | 없음 / 강함 | 돌풍 중 여부 |
| 환경 | `전체 경계` | 평상 / 경계 / 전투 | MASTER 7.8 전역 경계도 |
| 기록 | `최근 대사` | 문자열 최대 5개 | `bark_line_history` |

넣지 않는 값: 플레이어 실제 위치·체력·무기, 의심도 숫자, 다른 NPC의 상태, 맵 좌표.

### 입력 예시 (사용자 메시지)

```json
{"사건":"죽은 동료 발견","분류":"단서","알게 된 경로":"직접","방향":"앞",
 "거리":"중간","시점":"방금","반복":"처음","세부":{"동료 이름":"박 상병"},
 "역할":"경비병","성격":"겁 많은 신참","업무":"순찰","긴장도":"적극 수색",
 "몸 상태":"멀쩡","주변 동료":"없음","장소":"실내","밝기":"어두움","바람":"없음",
 "전체 경계":"평상","최근 대사":["오늘따라 조용하네."]}
```

### 출력 규격

```json
{"line":"박 상병? 정신 차려!","emotion":"놀람"}
```

- `line`: 1\~20자(공백·문장부호 포함), 한 문장.
- `emotion`: `의심` / `놀람` / `긴장` / `분노` / `안도` 중 하나.
- `llama-server`의 JSON 스키마 제약(또는 GBNF 문법)으로 이 형태 밖의 출력을 막는다. 제약을 못 쓰는 환경이면 한 줄 텍스트만 받고 `emotion`은 이벤트 기본값(`event_type.default_emotion`)을 쓴다.

모든 대사는 아래 검사를 통과해야 표시된다. 하나라도 실패하면 기본 대사를 쓰고 실패 코드를 `qwen_log.result`에 남긴다.

| 규칙 | 기준 | 실패 코드 |
| --- | --- | --- |
| 길이 | `StringInfo` 글자 수 1\~20(공백·문장부호 포함) | `TOO_LONG` / `EMPTY` |
| 한 문장 | 줄바꿈 없음, `<think>` 태그·따옴표는 미리 제거 | `MULTI_LINE` |
| 한국어 | 한글 비율 60% 이상, 영문 단어·숫자 없음(동료 이름 제외) | `NOT_KOREAN` |
| 정보 누출 금지 | 입력에 없는 고유명사·무기 이름·방향을 말하지 않음(동료 이름은 `세부`에 있을 때만) | `LEAK` |

| 반복 금지 | 같은 NPC 최근 5개·전체 최근 10개와 같으면 버림(문장부호·공백 무시 비교) | `REPEAT` |
| 감정 | 5종 중 하나, 아니면 이벤트 기본 감정으로 교체(대사는 살림) | — |
| 상황 일치 | 도착 시 추적 번호·행동 번호·생존·업무가 요청 때와 같음 | `STALE` |

### 성격 (persona)

NPC마다 성격 하나를 맵 JSON 또는 스폰 순서로 배정한다. 성격은 말투만 바꾸고 AI 수치에는 영향이 없다.

| ID | 이름 | 말투 | 예시(문소리) |
| --- | --- | --- | --- |
| `veteran` | 결단한 고참 | 짧고 단정적, 명령조 | "문 쪽이다. 확인한다." |
| `rookie` | 겁 많은 신참 | 더듬거림, 혼잣말 많음 | "뭐, 무슨 소리지…?" |
| `grumpy` | 투덜이 | 짜증, 귀찮음 | "또 문이야? 귀찮게…" |
| `cautious` | 신중한 감시병 | 차분, 상황 보고조 | "문소리 확인, 접근한다." |

## 우선순위·호출 제한·예외 처리

Qwen에는 한 번에 **1건**만 보내고 대기열은 **4건**까지만 둔다. 넘치는 요청은 우선순위가 낮은 것부터 바로 기본 대사로 돌린다.

### 요청 우선순위 점수

```
우선순위 = event_type.priority × 10      (1~5, 예: 죽은 동료 5, 바람 1)
        + 긴장도 단계 × 3            (평상 0 ~ 높은 위협 5)
        + (화면 중앙 가까움 ? 5 : 0)     (카메라 중심 6m 안)
        - 이번 추적에서 같은 코드로 말한 횟수 × 5
```

- 같은 NPC에게 0.5초 안에 여러 이벤트가 오면 점수가 가장 높은 하나로 합친다(나머지는 AI 인지에만 반영).
- 같은 사건(`world_event.id`)에 여러 NPC가 반응하면 화면 중앙에 가장 가까운 NPC 한 명만 Qwen을 쓰고, 나머지는 기본 대사 또는 대사 없음.
- 잡담(`SND_WIND`, 대기 중 혼잣말)은 대기열이 비었을 때만 보낸다.

### 호출 제한

| 항목 | 값 | 출처 |
| --- | --- | --- |
| 동시 요청 | 1 | MASTER 9.12 `qwen.json` |
| 대기열 | 4 | MASTER 9.12 |
| NPC당 진행 중 요청 | 1 (새 요청이 이전 요청을 무효화) | 설명서 14쪽 |
| 응답 대기 | 실제 시간 2초 | 설명서 15쪽 |
| 적 1명당 대사 간격 | 3초 | MASTER 7.18 |
| 최대 출력 토큰 | 32 (JSON 포함) | MASTER 9.12 |

### 예외 처리

| 상황 | 처리 |
| --- | --- |
| Qwen 꺼짐·서버 없음 | 모든 이벤트를 기본 대사로. 경고 로그 1회 |
| 2초 초과 | 기본 대사 출력, 늦게 온 응답은 버리되 검증을 통과하면 캐시에는 저장 |
| 검증 실패 | 기본 대사, 실패 코드 기록. 연속 5회면 이번 세션 Qwen 중지 |
| 요청 도중 NPC 사망 | 요청 취소, 응답 버림 |
| 요청 도중 업무 변경(예: 수색 → 교전) | 응답 버림(`STALE`), 새 상황으로 다시 판단 |
| 일시정지·브리핑 중 도착 | 보류 → 재개 시 상황 일치 재검사 |
| 고정 시드 재현 모드 | Qwen 꺼짐, 기본 대사만(MASTER 13.3) |
| 기본 대사도 없음(데이터 누락) | 대사 없이 진행, 경고 로그. AI는 영향 없음 |

## 부가 기능

추가 이벤트 5종 외에 같은 데이터 구조로 붙는 기능이다. 모두 대사·연출 쪽이며, ②·③만 AI 인지에도 영향을 준다.

| # | 아이디어 | 내용 | 필요한 데이터 | 우선순위 |
| --- | --- | --- | --- | --- |
| ① | 반복 사건 단계 상승 | 같은 소리가 두·세 번째면 말투가 바뀜("뭐지?" → "또야?" → "누가 장난치나!") | 입력 `반복` 필드 | S |
| ② | 바닥재별 발소리 | 타일 ×1.2, 나무 ×1.0, 카펫 ×0.6, 야외 ×0.8. 대사에도 "타일 밟는 소리" 같은 상황 반영 | `floor_noise_mult` (맵 바닥 종류별) | S |

| ④ | 동료 이름 | NPC마다 호칭("박 상병")을 주고 죽은 동료·무응답 대사에 사용 | `npc_profile.callsign` | S |
| ⑤ | 사전 생성 + 실시간 혼합 | 개발 때 상황 키별 대사를 미리 뽑아 기본 대사 풀을 키우고, 실시간은 캐시에 없는 상황에만 쓴다 | `bark_fallback.source = pregen` | S |
| ⑥ | 상태값 디버그 보기 | F3에서 NPC를 클릭하면 마지막 입력 JSON·출력·지연·결과 코드를 표시 | `qwen_log` | S |
