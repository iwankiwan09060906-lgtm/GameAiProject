# 요구사항 정의서

Oct 22, 2026 · @기완

## 1. 문서 개요

이 문서는 2D 탑뷰 전술 슈팅·잠입 게임(Unity)의 기능·비기능 요구사항을 하나의 기준으로 확정한 정의서다. 팀 의견이 갈렸던 15개 안건은 2장에서 한 안으로 통일했고, 3\~9장의 모든 요구사항은 이 결정을 따른다.

- **목적**: 구현·검수 범위를 하나로 고정해 팀원 간 해석 차이를 없앤다.
- **범위**: 싱글 플레이, 로컬 처리, Windows PC. 네트워크·서버·계정·클라우드 저장은 제외한다.
- **근거 문서**: 상세 기획안(작성 기준일 2026-10-13), 기말 프로젝트 기획 질문지 의견 취합(2026-10-22, 익재·최기완·김성범 응답 Q01–Q71).
- **통일 원칙**: ① 구현·검수 부담이 작은 안을 우선한다. ② 세 사람 중 둘 이상이 같은 방향이면 채택한다. ③ 채택되지 않은 의견은 S/C 등급 기능으로 살릴 수 있으면 살린다. ④ 체력·피해량·거리·시간 같은 튜닝 수치는 초기값으로 두고 담당자가 테스트하며 조정한다.
- **결정 상태**: 2장은 팀 회의 전의 기본 확정안이다. 회의에서 바뀌면 해당 행만 고치고 3\~9장은 "결정 연계" 열의 번호로 찾아 함께 수정한다.

### 우선순위·단계 정의

| 등급 | 의미 | 적용 기준 |
| --- | --- | --- |
| M | 필수 | 기말 제출에 반드시 포함. 빠지면 미완성으로 본다 |
| S | 권장 | M이 끝난 뒤 일정 여유가 있을 때 구현 |
| C | 여유 | 모두 끝난 뒤 시간이 남을 때만 구현, 빠져도 무방 |
| X | 제외 | 이번 범위에 넣지 않음 |

단계는 **중간**(중간발표 시연에 필요) 또는 **기말**(기말 제출까지 구현)로 표기한다. 중간에 만든 기능은 기말에서도 유지한다.

| 7 | 피격 반응·낮은 엄폐물 | 피격 시 적색 깜빡임 0.1초와 피격음만. 경직·밀림·둔화·무적 시간 없음. 낮은 엄폐물은 총알 차단·시야 투과(반엄폐형), 높은 엄폐물은 시야·총알 모두 차단(완전 차폐형) | 익재·최기완이 시야 투과에 일치, 밀려남은 조작감을 해쳐 제외 |

| 9 | 무전 범위·전체 경계 | 무전: 마지막 목격 위치를 **모든 적**에게 전달. 외침: 반경 12m 적에게 전달. 수신자는 의심 상태로 조사하고 재전파하지 않음. 발신은 5초에 1회, 발견 사건당 최대 2회. 전역 경계도는 개별 적 상태 최댓값의 3단계 표시값이며 경계·전투 단계에서 수색 시간 ×1.2 반영(S) | 익재의 무전/외침 구분, 최기완의 표시 전용, 김성범의 AI 반영을 절충 |
| 10 | 교전·행동 우선순위·통로 | 탄창·재장전 포함, AI 예비 탄약 무제한. 사거리 안에서 정지 사격, 밖이면 접근. 우선순위: **사망 > 눈앞의 플레이어 > 새 소리 > 수색 종료**. 익재의 "시간 종료"는 수색 종료로 해석(미션 시간 종료는 미션 매니저 소관). 좁은 통로: 우선순위 낮은 적이 가까운 빈 칸으로 비켜주고 2초 이상 막히면 임시 겹침 | 익재·최기완이 재장전 포함에 일치, 수색 종료를 가장 낮게 두는 쪽이 추격 반응이 자연스러움 |
| 11 | 시야 밖 정보·화면 배치·일시정지 소리 | 시야 밖 문은 마지막 본 상태 유지. 방문 지형은 윤곽 유지 + 30\~40% 회색조, 미탐색은 완전 암전. HUD: 좌하단 체력, 우하단 무기·탄약, 좌상단 목표·타이머, 우상단 전역 경계 3단계, 적 머리 위 ?·!. 일시정지는 모든 소리 정지 후 재개 시 이어서 재생 | 익재·최기완이 마지막 상태 유지에 일치. 화면 담당이 시안으로 미세 조정 가능 |
| 12 | 난이도·설정 범위 | 기본 "보통" 1단계가 M, 쉬움·보통·어려움 3단계(배율 ×0.8/1.0/1.2)는 S. 난이도는 미션 입장 전 메뉴에서 선택하고 플레이 중 변경 불가. 설정 항목은 음량(전체/효과음/배경음)·전체화면·해상도. 마우스 감도·키 변경은 제외(마우스 커서 직접 조준). 설정은 오버레이, 메뉴와 게임은 씬 분리 | 일정 위험을 줄이면서 3단계 희망도 살림 |

| 14 | 저장 실패·손상 복구 | 저장 실패 시 안내 후 1회 재시도, 계속 실패하면 기록 없이 게임 진행. 손상 파일은 .corrupt로 보존, 정상 .bak이 있으면 복원, 없으면 사용자 동의 후 초기화. 저장은 임시 파일에 쓴 뒤 교체 | 세 사람 모두 재시도 + 복구 방향이고 동의 절차가 가장 안전 |
| 15 | 성능 합격 기준 | 적 20명 동시 활성에서 60fps, AI 처리 2ms 이하(렌더링·물리 제외, 감지·상태·경로·이동·공격 판단 전체). 순간 지연은 최저 45fps(22ms)까지 허용하되 0.5초 넘게 지속 금지, 33ms 초과 프레임 0회. 측정 구간은 적 20명 추격·교전 동시 60초. 검수 PC는 팀원 PC 중 최저 사양 | 두 팀원의 측정 조건이 20명으로 같음. 50명 안은 일정상 채택하지 않음 |

## 7. 제약 사항과 가정

### 제약 사항

- **엔진·환경**: Unity 6000.3.24f1, Windows PC, 싱글 플레이, 로컬 처리. 학습형 AI는 쓰지 않고 규칙 기반 FSM과 행동 트리만 쓴다.
- **에셋**: 사용이 허용된 무료 에셋 또는 직접 제작물만 쓰고 출처를 기록한다. 생성 도구는 수업 규정을 확인한 뒤에만 쓴다.
- **일정**: 중간발표 11/17, 기말 12/15. 중간발표 3일 전(11/14)부터는 기능을 바꾸지 않는다.
- **작업 시간**: 최기완 주 5\~10시간, 김성범 주 약 7시간, 익재 하루 2\~3시간 범위에서 일을 나눈다.
- **제외 범위**: 인질 구출, 섬광탄, 잠금·열쇠·문 파괴, 측면 이동, 문 경로 우회 소리 전파, 얇은 벽·유리 관통, 마우스 감도·키 변경, 100×100 대형 맵, 네트워크 기능.

### 가정

- 최기완 문서의 "익재"와 김성범 문서의 "이익제"는 같은 사람으로 보고 "익재"로 적었다. 이름이 다르면 8장 역할표만 고치면 된다.
- 팀장은 어느 응답에서도 정해지지 않았으므로 맡은 영역이 가장 넓은 최기완으로 가정했다. 팀 회의에서 바뀌면 2장 #16을 수정한다.
- 익재의 "2\~3시간"은 하루 기준으로 보았다. 주당 기준이면 S 등급 기능을 먼저 줄인다.
- 수업 요구사항 원문이 확인되지 않은 항목은 A\* 직접 구현, 생성 도구 허용 여부, 공식 중간·기말 일정이다. 원문과 다르면 원문이 우선이며 2장 #5·#17·#19를 고친다.
- 모든 수치(피해량, 거리, 시간, 배율)는 초기값이다. 테스트 후 바꿔도 요구사항 변경으로 보지 않는다. 단, 2장에 적은 대소 관계(예: 소총 피해 > 권총 피해)는 유지한다.
